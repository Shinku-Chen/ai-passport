# What to Eat Today

A food-roulette decision helper for the AI Passport. Not sure what to eat? Hold
the buttons to spin through a food lottery and release to land on a random food.

This is the application built on this `feature/cheerful-goodall` branch.

## Interaction

Three keys drive the app (button callbacks run in the button task, so they stay
non-blocking; the animation loop runs on an LVGL timer):

- **Press any key (UP / DOWN / OK)** — draw lots: pick this round's type at random,
  then start spinning from a random frame of that type.
- **Release** — stop on the last frame shown; the frame already carries the dish or
  place name, and that is the result.
- **OK (long press)** — toggle the render path (LVGL partial redraw / direct panel
  blit); hardware A/B only.

Each of the two types is a frame sequence, chosen with equal probability per press:

| Type | Badge label | Content | Frames / rate |
| --- | --- | --- | --- |
| Place roulette | `PLACE` | McDonald's, a glasshouse, stir-fry, sushi… | 20 frames / 10 fps |
| Dish roulette | `DISH` | Shaxian snacks, Lanzhou noodles, burger, hotpot… | 21 frames / 20 fps |

The "release" is detected by polling `bsp_button_read_mv()` (this BSP has no
RELEASE event): released ≈ 3300 mV, pressed < 2000 mV.

## What it does

- A top-right battery indicator (read from `bsp_battery_soc()`) shows the live
  charge, so it degrades gracefully when the reading is `-1`.
- Auto-poweroff: the app powers itself down after a period of idle.
- No PSRAM needed: the food frames are embedded as LVGL `LV_COLOR_FORMAT_I8`
  index-color binary (embedded via CMake `EMBED_FILES`), so the animation runs
  from Flash without a frame buffer.

## Firmware / build

The frames come from `main/eat_what_g1.bin` / `main/eat_what_g2.bin` (256-color
palette + pixel index per frame, generated by `tools/generate_eat_what_assets.py`).
The app keeps a few lazily-built `lv_image_dsc_t` (one small object per frame,
the image data stays in Flash) so it fits the memory budget.
