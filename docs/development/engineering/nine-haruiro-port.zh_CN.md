# 9-nine- 春色春恋春熙风：离线阅读器移植

本分支（`feature/port-nine-haruiro`）把 GalGame 框架改造成《9-nine- 春色春恋春熙风 /
9 -Nine-: Episode 3》的完整离线阅读器，运行在 AI Passport（ESP32-C3、8 MB Flash、无
PSRAM、320×240 ST7789P3、三键）上。它是本设备六部移植中的一部；本分支只包含这一部。

## 1. 固定来源与范围

| 项 | 值 |
| --- | --- |
| 来源仓库 | `https://github.com/xuanyide01/9-nine-rw5` |
| 固定提交 | `6a8907a5ae576f4377abe4b74f15bd9af13efe07` |
| 工程 | `nine-haruiro-rw5`（REDMI Watch 5 的全年龄中文主线移植） |
| 来源入口 | `c01a.txt/*start` → graph 节点 `n0` |
| 剧情包输入 | `src/common/graph.js`、`src/common/story/**`、`src/common/chunk-codec.js` |
| 引擎参照 | `src/common/engine.js`（PERSISTENT_KEYS、条件、effects、顺序、回退、试读、跳转上限） |

固定快照是唯一权威。它包含**非 R18 中文主线**：78 个 graph 节点、10,659 句正文加 1 条 OP
标记、13 处选项、15 章、2 个结局里程碑。该快照本身排除了 11 个 R18 场景与全部语音；本移植
不重建、也不臆造这些内容。下文“完整”均指相对该固定快照的完整。

原始 PC 脚本**不重建**：已加工好的 Watch graph 才是权威。打包器只把它编译成紧凑二进制，
不解释原始 TJS。

## 3. 资源包格式

两个二进制文件嵌进应用：

| 文件 | 最终大小 | 内容 |
| --- | --- | --- |
| `assets/nine/haruiro/nine_script.bin` | 778,099 B | 头/表/正文块/字符串 |
| `assets/nine/haruiro/nine_images.bin` | 5,773,507 B | JPEG/索引图、OP 帧、音频 |

`nine_script.bin`（`NINESC2`，小端，无本机指针）包含节点、帧、正文块、视觉、图层、变量、
条件、效果、边、章节、结局与鉴赏表，以及有界字符串池。正文按最多 8,192 字节的 zlib 块存放；
每帧记录 `(块, 偏移, 长度)`，打包器保证块内有 NUL。整文件 CRC32 覆盖每一个字节。

`nine_images.bin`（`NINEIM1`，版本 2）包含：

- 打包阶段 **320×180** 的 JPEG 背景/CG（质量 38）；
- 256 色索引立绘/表情裁片（8 行一条 zlib 块），保留身体透明与逐表情差分；
- 493 帧 OP（来源 5 fps，完整 98.62 秒）；
- 两条 16 kHz 单声道 IMA ADPCM 音轨；
- 3 张标题主视觉与标题 Logo。

每个图像记录的 CRC 覆盖其全部负载；音频记录另有 CRC。启动时先校验两个包再建界面；包损坏会
显示可见提示并让阅读器停在不可读状态，而不是画出半解码画面。CRC 统一使用 256 项查表实现
（`nine_crc32.c`）。旧的逐位循环使启动校验形成约 6.5 秒的 CPU 长阻塞（Lead 真机日志有
IDLE-WDT 警告）；查表版保留全部整文件/逐资源 CRC，主机吞吐约 3.9 倍，按旧 6.5 秒折算
~12.2 MB 启动 CRC 约 1.7 秒。没有喂狗、关闭或放宽 WDT；该估计仍需 Lead 真机复测。

## 4. 阅读器与 VM

VM 直接解释 `engine.js`，不是另造脚本语言：

- `locate` 在节点边界执行节点 effects 与 complete，再返回正文/OP/选项/结局；顺序 `nexts`
  取第一个匹配条件；
- 选项按条件筛选；筛选后为空时回退到**全部**选项，与 `visibleChoices` 一致；
- 条件视图只从永久记录覆盖 `loop1`，其余永久键留在永久记录里（与 `flags()` 一致）；
- `applyEffects` 把 `PERSISTENT_KEYS` 写入永久记录，其余写入周目标记；章节试读
  （`progression='chapter'`）抑制所有永久写入；
- 打包时把 `complete` 折叠成永久 effects，包括 `true` 结局的 `clear_true`；
- 图遍历上限 500 跳；非法包与越界游标返回明确错误视图；
- 保留 24 个状态快照供 `previous`，且不保存指向正文缓存的指针：正文在任何其他包访问前复制。

持久化把三件事分开：

1. **周目变量**（`flag[]` 与 `flag_set` 位图）随存档槽或自动记录保存，New Game 清零。
2. **手动存档**为 30 个 blob（`s01`…`s30`），每个含节点、帧下标、正文页、试读标记、全部
   周目/永久变量和 CRC。读档先校验 CRC 与作品身份，再改 live 状态。来源就是 30 槽；界面用
   4 行滑动窗口呈现。
3. **永久记录**（`perm`）只由永久 effects 写入；普通读档时覆盖到存档快照上（试读快照除外），
   等价于 `Object.assign({}, session.progress, this._progress)`。因此看完结局、解锁主视觉
   后，再读旧手动档仍保留永久资格，同时恢复该档的位置与周目标记。

自动记录（`auto`）1.5 秒节流，深睡前强制落盘；章节试读从不写它。

启动是硬门禁而非尽力而为：`bsp_lvgl_set_landscape(true)` 必须在 BSP 锁内成功，
`nine_app_init` 必须建好界面，并强制 `lv_refr_now()` 提交首帧**之后**才开背光。
横屏或初始化失败会画一张居中的 16 px 中文错误页（生成的 `nine_cjk_16`，不是默认
Montserrat）然后停止。队列/任务/按键创建失败同样显示错误页并回滚已创建的队列/任务、
停止音频。正文/图像解码失败会冻结在该帧并显示提示，菜单可以重试解码、读档或回标题，
但推进不能跳过缺失内容。

## 5. 界面与操作

保留框架页面，重排为 320×240，由应用层（`main/nine/nine_app.c`）驱动。画面画在 6 条
256×24 RGB565 条带（每条 12,288 字节）上；阅读画面为完整 320×180。
透明名牌行 y160..179 直接叠在画面上（无黑带、无胶囊），文本框占 y180..239
（60 px），正文不进入画面。OP 仍为完整 320×180，标题/纯 CG 仍为 320×240。
名字、自动与临时提示在叠加行各用固定槽位；阅读页页码 HUD 不创建（按产品要求），
真正的分页、存档页号与短按翻页语义不变。16 px 正文三行（20 px 两行）。
256×144 画布在面板上放大 1.25× 到 320×180 的画面区（原因见 §7）。

| 页面 | 短按 OK / 上 / 下 | 长按 OK |
| --- | --- | --- |
| 启动 | 进入标题 | — |
| 标题 | 移动 / 选择 | — |
| 阅读 | 三键都立即推进；打字中的页先补全，同一次按键继续翻到下一页/下一句 | 游戏内菜单 |
| 选项 | 上/下选择，OK 确认 | 游戏内菜单；返回后完整选项与选择位置不变 |
| 菜单 / 存读档 / 设置 / 历史 / 鉴赏 / 章节 / 音乐 | 移动 / 选择 | 返回 |
| CG 浏览 | 上/下切换差分，OK 返回 | 返回 |
| 结局 | 回标题 | 回标题 |

阅读页的额外手势：

- 短按一定推进页/句游标，不会只补全而不推进。
- **按住上**：长按阈值到达立即进入下一句，跳过本句剩余分页、打字与自动等待；持续按住时
  每个输入 tick 至多推进一整句，不累积额外的 90/120 ms 句间等待，也不做补帧循环。松开
  立即停止且不补短按；选项/结局/OP/资源错误停住。普通短按仍逐完整分页。
- **长按下**：切换自动阅读。整页打完后才开始 1.2 秒计时；自动中手动短按会关闭自动，
  **并且仍然推进正文**。
- 任意键长按会吞掉 BSP 可能在同一释放上报出的 CLICK；新的 PRESS 清除该锁存。

标题主视觉 1/2/3 按来源 UI 的永久 loop/true 记录解锁：第 2 张需要 `loop1`/`loop_hk`
或 `true`/`cf_hk`/`clear_true`，第 3 张需要两组都有。transient `titleBg` 里程碑
（n40 写 1、n77 写 2）不会撤销已获得的解锁，所以二周目到 n40 仍保有 3 张主视觉。
鉴赏室开放全部 18 组/100 张差分（来源没有门控）、15 章试读和 2 首 BGM。章节试读以
`preview` 启动 VM，从不写永久进度。

阅读页与选项页长按 OK 都打开游戏内菜单。菜单动作不移动剧情 VM、不授予永久资格。
从阅读页菜单返回恢复原正文子页；从选项页菜单返回重新渲染完整选项并保留原
`choice_sel`。手动存/读档、自动进度与 Continue/重启沿用现有存档格式携带正文子页
（格式不变）；CRC 合法但页号超出当前帧页数的旧档由 `paginate()` 夹到最后一页。

## 6. 字库

`tools/nine_font.py` 用来源的 `nine-text.otf` 生成 16 px 与 20 px 的 LVGL 子集（4 bpp）；
仅少数该字体没有的界面码位回退到微软雅黑。字符集取“包内正文 + `main/` 下全部 C 字符串字面量
+ ASCII + 上一版清单”的并集。最终覆盖 **2,425 个码位**（2,350 个剧情字符），0 缺字；生成后
回读 LVGL cmap 与字形数据逐像素校验。`tools/nine_font_check.py` 会独立检查剧本每个字符在
两档字体里都有字形，并在 host 门禁中运行。

## 7. 内存与 Flash 预算

目标：ESP32-C3、8 MB Flash、无 PSRAM、ESP-IDF 5.5.3、`factory` 应用分区 0x7f0000
（8,323,072 B）。

### Flash（最终固件）

| 项 | 字节 |
| --- | ---: |
| 剧情包 | 778,099 |
| 图像/音频包 | 5,773,507 |
| 资源包合计 | 5,747,788 |
| 编译后中文字库（16+20 px） | 799,119 |
| Flash Data 合计 | 6,614,160 |
| Flash Code | 560,652 |
| 应用镜像 | 8,062,448 / 8,323,072（96.9%，余 260,624） |
| 合并整机镜像 | 8,127,984 |

### DRAM（链接期）

| 区域 | 字节 |
| --- | ---: |
| DRAM 总量 | 321,296 |
| 已用 | 160,526（50.0%） |
| `.bss` | 82,384 |
| `.data` | 7,704 |
| DRAM `.text` | 70,478 |
| 链接期余量 | 160,770 |

运行期从该余量分配（预算，不是实机峰值）：

| 项 | 字节 |
| --- | ---: |
| 画面画布：8 × 256×24 RGB565 | 98,304 |
| LVGL 绘制缓冲：320×20 RGB565 | 12,800 |
| 输入/音频/LVGL/主任务+定时器+空闲任务栈 | 约 28,160 |
| 留给 LVGL 对象、NVS、codec 缓冲 | 约 45,900 |

最大单次分配 **12,288 B**（一条带）；没有任何 >32 KB 的连续分配。LVGL 改用系统堆
（`LV_USE_CLIB_MALLOC`），不再预留 64 KB 私有池，对象与画布共享同一份预算。用真实目标
flags 的 `-fstack-usage` 复核最深的阅读器调用帧：`nine_vm_save_decode` 1,136 B、
`nine_image_show_visual` 800 B、`nine_app_init` 592 B、`load_slot` 1,072 B、`jpeg_decode` 224 B、
`jd_decomp` 48 B；8,192 B 输入任务栈不紧张。音频任务帧 544 B。

### 图像管线与真实取舍

资源包保留 **320×180** 舞台（来源 432×243，16:9），因此包与来源对账保留完整构图、立绘锚点
与表情差分。C3 链接期只剩约 160 KB DRAM；320×180 RGB565 画布（115,200 B）加上任务栈与
LVGL 对象放不下。阅读器因此合成到 **8 条** 256×24 有界条带（共 98,304 B）：阅读/OP 用前
6 条（256×144 → 320×180），标题与 CG viewer 用全部 8 条（256×192 等比 cover → 320×240）。
256×144 放大 1.25× 到 320×180；全屏多出的 60 px 由标题/CG 图覆盖，不再留黑带。这是对打包阶段的真实 0.8× 降采样（相对源 432×243 为 0.59×），明确写入文档而非
隐去；提高到 288×162 还需约 19 KB 堆，尚未验证。若以后释放出 RAM，把 `NINE_IMAGE_W/H`、
`nine_image.c` 的图层缩放与参考测试改回 320×180 即可。

其他已量化的取舍：

- 打包阶段 JPEG 质量 38；索引立绘/表情 192 色、8 行 zlib 块（最大块 2,080 B）。
- OP：完整 493 帧 @5 fps（完整 98.62 秒，1,989,799 B）。
- BGM：来源 36 kbps Opus（895,865 B）→ 16 kHz 单声道 IMA ADPCM（1,518,396 B）。
  8 kHz 版本（759,264 B）被否决：明显发闷，而 Flash 预算足够 16 kHz。来源快照本身无语音。

## 8. 构建与运行

```bash
# ESP-IDF 5.5.3 环境
./tools/validate.sh --static      # 仓库检查 + 全部 host 测试
./tools/validate.sh --firmware    # 全新构建、合并镜像、verify、归档
idf.py -p <port> flash monitor    # 本轮不做设备刷写
```

```bash
python tools/nine_pack.py --source <nine-haruiro-rw5> --episode haruiro \
    --out assets/nine/haruiro --jpeg-quality 38 --op-fps 3
```
