# 爱上火车二六线 —— AI Passport 移植

## 1. 范围与输入

输入是手环移植版《爱上火车》二六线：

| 项目 | 值 |
| --- | --- |
| 上游 | [`xuanyide01/maitetsu-rw5`](https://github.com/xuanyide01/maitetsu-rw5) |
| 固定提交 | `9c008406853affe973ceb80f62128696054365e7`（RW5 0.1.3） |
| 输入摘要 | `082babe851a5efd6a4c6ab28bb4363fc1e8bf35448bea32466abe926ee8d07f2`（34 个分块、画廊、UI 图、标题曲与 `converted/text.json` 的 SHA-256） |
| 剧情 | 四章：正和四十一年·小仓、御一夜旅行、小仓风暴、尾声 |
| 段落 | 354 + 345 + 368 + 470 = 1,537 |
| 场景 | 34 个分块里 675 个不重复的合成快照 |
| 画廊 | 6 组、35 张 CG（含差分） |
| 选项 | 无：RW5 引擎在这条线上调用 `choose()` 会直接抛错，剧情是线性的 |
| 标题曲 | 283.88 秒、4 kHz 单声道 16 位 PCM |

这是该 RW5 移植的**完整内容**，**不是原作的全部路线**。固件里没有任何地方暗示
相反：关于页、README 与本文都写明只有四章。

源检出按只读处理：生成器只读取它，所有输出都是确定性的（无时间戳、图像顺序稳定）。

## 2. 结构

应用保留本分支的 GalGame 框架：同样 19 个逻辑屏、三键交互、分页、存档 / 自动进度
分离与永久解锁。内容层被替换；源数据放不进骨架的地方做了最小扩展：

| 框架限制 | 本作 | 改动 |
| --- | --- | --- |
| 竖屏 240×320 | 横屏 320×240 | BSP `bsp_lvgl_set_landscape(true)`；画面区 320×180（精确 16:9），下方 60px 对话框 |
| 32 位 CG 解锁位图 | 35 张 CG | `gal_unlock_t.cg` 改为 64 位；NVS 记录升到 v2，v1 可迁移 |
| 8 个 CG 缩略图、只显示前 8 项 | 35 张 CG | CG 鉴赏按每页 8 张分页，33..35 也能看到 |
| 场景是程序绘制的渐变 | 675 个分层场景 | 新增媒体包与条带式 RGB565 JPEG 解码器 |
| 每句一张图 | 背景 + 最多两个合成补丁 | `gal_line_t.scene`；界面先画背景，再按矩形贴补丁 |
| 方波音乐 | 一首 283.88 秒的曲子 | IMA ADPCM 解码 + 线性插值到 16 kHz 播放 |
| 3 个存档槽 + 周目标记 | 四章覆盖面 | 存档与自动进度增加 `run_mask` |

### 2.1 媒体包

`assets/maitetsu/maitetsu_media.bin`（5,773,642 字节，`MTMEDIA1`）：

- 759 张图像：353 张背景、335 个合成补丁、35 张 CG、35 张 64×36 缩略图、1 张标题主视觉。
- 每张图像切成独立的 30 行 JPEG 条带。量化表与 Huffman 表按质量档共享一次
  （共 4 个前缀），所以一条条带只有 35 字节扫描头加熵编码数据。设备上不会出现
  整图解码缓冲：自定义的 LVGL 图像解码器每次只解一条 320×30 的 RGB565 条带
  （19,200 字节）。
- 场景按「背景 + 补丁」存储。补丁是立绘按精确矩形与背景合成后的结果，透明与表情
  完全保留，背景在场景之间复用（675 个场景只用 353 张背景）。
- 媒体包带表区 CRC32 与每张图一个 CRC32：表区损坏会让 `maitetsu_pack_init` 失败，
  条带损坏会在该图第一次解码时失败。解码失败发生在 LVGL 任务里时，会在输入任务的
  下一拍收到并置起媒体故障：关闭阅读资格、显示红色资源错误面板、拒绝继续推进；
  不会用陈旧或半解码的画面继续演。
- 按图描述（宽、高、首条带、条带数、前缀、CRC）生成成 `const` Flash 表，
  `maitetsu_pack_image()` 返回这张表里的元素，指针在整个进程内稳定。LVGL 的
  `info` / `open` / `get_area` 回调因此不会看到共享或复用的临时对象；`init` 会
  逐项与包内表比对，不一致直接拒绝。

质量参数为 `背景 60 / 补丁 74 / CG 68 / 缩略图 74 / 标题 82`（Pillow 基线 JPEG，
4:2:0）。源背景是 300×169 的 JPEG，RW5 应用会把它放大到 432×243；目标以 320×180
保存，等于同样的信息量、略小的尺度。这是真实的重新压缩 —— 在这里写明，不宣称无损。

### 2.2 文本与内容表

`tools/maitetsu_assets.py` 重新生成 `main/gal/gal_content.c`（1,537 条对白、
1,542 个事件、4 张章节过场、1 个结局、35 张 CG、4 章、6 段回想、1 首曲子）与
`main/gal/maitetsu_assets.c`（675 行场景、335 行补丁、媒体下标）。正文保存为字符串
字面量，所以 `tools/gal_font.py` 能看到全部段落，生成的字体子集覆盖所需的 1,682 个
字形（16px 与 20px，4bpp）。

生成器在写文件前校验源结构：章节段数、675 个不重复场景 id、所有图层矩形都在
432×243 画面带内、6 组 35 张画廊条目、`converted/text.json` 与每一段一致。

### 2.3 音频

标题曲是完整的源曲：4 kHz 下 1,135,520 个样本，按独立 256 样本块编码成 4 位 IMA
ADPCM（4,436 块、585,588 字节，含 36 字节包头与 CRC32）。实测重建 SNR 为
22.16 dB —— 源本身已经限带到 2 kHz，这是 4 位表示的真实代价。播放时逐块解码并线性
插值 ×4 到 16 kHz（I2S/ES8311），因此时长精确为 283.88 秒。没有截短，也没有用合成
音替代。播放任务按 16 ms 一片喂 I2S DMA，并在每轮完整播放后记录一行有界计时
（`样本数 / 墙钟毫秒`）；这一行只用于判断设备端是欠载还是时钟问题，不改变采样率。

## 3. 操作

横屏 320×240，三键（逻辑上的上 / 下 / 确定；BSP 按电平映射，机身方向变化不改变语义）：

| 页面 | 短按 OK / 上 / 下 | 长按 OK | 长按上 | 长按下 |
| --- | --- | --- | --- | --- |
| 阅读 | 推进一页/一句；逐字显示中同一次按键补全当前页并推进，不需要第二次按。长句仍按分页单元逐页推进。 | 游戏内菜单 | 立即跳到下一句（跳过当前句剩余分页、打字机与自动间隔），按住每个输入拍（50ms）推进一句，松手立刻停 | 自动阅读开 / 关 |
| 章节过场 | 继续 | — | 直接快进过去 | 自动阅读开 / 关 |
| 选项 | 上下移动，OK 选择 | 返回阅读页 | — | — |
| 列表 / 菜单 / 存读档 / 设置 / 鉴赏 | 移动 / 切换 / 执行 | 返回 | — | — |

快进在选项、结局和其他需要确认的页面自动停住，绝不替玩家选择。长按只产生长按动作：
松手不会补发一次短按（测试覆盖）。自动阅读在当前页显示完后等 900ms 推进；自动开启时
短按仍然推进，且不会关掉自动。

### 3.1 试读与通关

从剧情鉴赏进入任何一章、或回放一段回想，都会开始一局**试读**（`preview = 1`，
`run_mask` 重置成只剩这一章）。试读是显式持久状态，不是只看章节覆盖面：即使从第一章
试读一路读到结局，结局页也会标注为试读，**不会**授予永久结局与派生的通关资格。
`preview` 随手动存档与自动进度保存，所以中途存读档、继续或重启都不能把它洗成正式
周目。只有**开始游戏**会清除 `preview`，正式周目读完四章到结局才记录一次结局。
已有的永久解锁不会被撤销。preview 字段出现之前的旧记录（v1–v3）读入时置
`preview = 1`：保留阅读位置，但不能据此新授结局。

### 3.2 资源失败

- LVGL 解码器里任何 CRC / 条带失败都会置起媒体故障。按键路径在解释这次按键之前
  先收口（`input_task` 会先送按键、再 tick），所以失败之后到达的按键绝不会跳过那段
  没有成功显示的正文，也不可能从没显示的最后一句滑进结局。
- 故障期间拒绝一切阅读动作：推进、快进、自动、章节过场、选项执行、章节/回想入口、
  开始游戏、继续、读档。菜单、设置、鉴赏室、关于与离开阅读页仍然可用。
- 错误层是屏幕根对象上的全屏层，位于所有页面之上：标题页、CG 浏览、CG 列表、鉴赏室
  都保持可见，切页也不会把它压下去。第一次显示错误的 LVGL 锁失败时，错误保持
  “待提交”，下一拍重试；重试绝不恢复 `media_ok`。
- 启动把方向与首帧当硬依赖：`bsp_lvgl_set_landscape()` 失败就停止启动；首帧刷新拿不到
  锁时保持背光关闭，直到第一次按键，而不是显示一帧未确认的画面。

## 4. 持久化

| NVS 命名空间 | 键 | 内容 | 格式 |
| --- | --- | --- | --- |
| `galcfg` | `cfg` | 文字速度、字号档、自动阅读、对话框透明度 | 不变 |
| `galsave` | `slots` | 3 个槽位：事件、页、章节名、周目标记、`run_mask`、`preview` | v4；v1–v3 迁移（preview = 1） |
| `galprog` | `pos` | 自动进度：事件、页、周目标记、`run_mask`、`preview` | v4；v1–v3 迁移（preview = 1） |
| `galunlock` | `bits` | 永久 CG（64 位）/ 章节 / 结局位图 | v2；v1 迁移 |

读档会先校验长度与版本，再改动运行状态；损坏或截断的记录被忽略，内存中的旧状态
保持不变。

## 5. 预算

| 项目 | 字节 | 说明 |
| --- | --- | --- |
| App 分区 | 8,323,072 | `partitions.csv` 的 factory，起点 `0x10000` |
| 应用镜像 | 7,759,632 | `idf.py size` 的镜像合计 7,759,520 |
| — 媒体包 | 5,773,642 | 759 张图像 / 3,994 条条带 |
| — 标题曲 | 585,588 | 4 位 IMA ADPCM，完整 |
| — 代码、正文、字体 | ≈1,388,000 | 1,682 字形 × 2 档 × 4bpp |
| 分区剩余 | 563,440 | 6.6 % |

静态 RAM（`idf.py size`，目标 ABI）：DRAM 321,296 字节中用 211,508（剩 109,788），
`.bss` 134,296，`.data` 7,324。媒体包解码的条带缓冲占 `.bss` 19,200 字节，JPEG 工作
池 4,096 字节，LVGL 图像描述符 21,504 字节；按图描述放在生成的 Flash 常量表里
（12,144 字节），`maitetsu_pack_image()` 返回稳定指针，调用之间不再共享临时对象。`-fstack-usage` 里最大的静态栈帧是
`show_line` 1,104 字节（1 KiB 的翻页缓冲），其次是 `gal_save_load` 416、
`maitetsu_pack_band` 256；输入任务与音乐任务栈 4 KiB，LVGL 任务 7,168 字节。

## 7. 未验证

- **本轮没有设备测试。** 固件已完成构建、合并与静态校验；没有刷写（未获授权）。
  横屏方向、实体按键手感、音频输出、背光时序与长时间稳定性都未在硬件上确认。
- 主机集成测试驱动真实 LVGL 解码器（`info` / `open` / `get_area` / `close`）并逐字节
  对比结果，但设备上的绘制路径（场景的局部刷新）没有在屏幕上观察过。启动日志只声称
  “首帧刷新请求在 LVGL 锁内返回”（`lv_refr_now`），不声称面板真正刷完。
- 横屏与首帧是硬依赖：LVGL 锁或 `bsp_lvgl_set_landscape(true)` 失败时，固件在绘制前
  停止，不会以错误方向继续运行；首帧刷新拿不到锁时保持背光关闭，直到第一次按键。
- ADPCM 的 22.16 dB SNR 是对源 WAV 的离线测量；ES8311 扬声器上的主观听感未验证。
- 图像质量是为装进 8 MB 分区选的 `背景 60 / 补丁 74`；复核者可能有不同的取舍。
  改动只需重新生成媒体包并重新构建。
