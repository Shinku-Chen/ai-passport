# Summer Pockets REFLECTION BLUE Reader

This branch (`feature/port-summer-landscape`) turns the AI Passport into a
landscape 320×240 reader for the RW5 **Summer Pockets REFLECTION BLUE** source
snapshot. The source is the converted Xiaomi Vela project, not the Windows
engine: its current range is what this firmware reproduces. It does not claim
to restore PC-only content that the RW5 source already omitted.

## 1. Source scope

The read-only snapshot is
`assessment-games/repos/summer-rw5` (recorded commit
`28f8a41c3e77b57c9e519816b27fbc1f1ed94866`). The packer and audit read it
directly; no old build report is trusted.

| Item | Current RW5 source | Packed |
| --- | --- | --- |
| Scenes | 422 (`converted-story/*.json`) | 422 |
| Ops | 150,453 | 150,453 |
| Dialogue/narration ops | 81,040 | 81,040 |
| Choice groups / items | 188 / 495 | 188 / 495 |
| Map groups / items | 27 / 918 (all in scene 281) | 27 / 918 |
| Routes / chapter entries | 14 / 252 | 14 / 252 |
| CG groups / variants | 136 / 712 | 136 / 712 |
| Unique image files | 1,324 (292 portraits + 1,032 scenes) | 1,324 + logo |
| Endings | 14 (`FLOW_ENDINGS`) | 14 |

The source itself has five heroine routes plus ALKA, Pocket and the epilogue;
Miki, Shizuku and Umi personal routes are already absent. The source also has
no BGM, voice, video, complex animation or playable minigames. This firmware
does not invent them. `title-progress.js` is the authority for clear flags,
ReSTART stages and title actions; `FLOW_ENDINGS`, `HEROINE_ENDINGS` and
`CLEAR_FLAGS` are copied into the pack metadata and checked by the audit.

`names.js` normalization is applied while packing: the compatibility ideograph
U+4C37 becomes U+7DAB; a dotted/spaced full-name form collapses to
U+7DAB U+6587 U+5FB7 U+65AF; the ASCII romanization "Tsumugi" maps to that full
name; and the Arabic question mark U+061F becomes the fullwidth question mark
U+FF1F. All 2,842 source speaker labels use `fullName`, so U+7DAB becomes
U+7DAB U+6587 U+5FB7 U+65AF there as well; scene/route/chapter labels use the
same expansion. The dialogue body itself is unchanged. This is why the font
subset has no U+061F missing glyph.

## 2. Target layout and controls

| Area | Layout |
| --- | --- |
| Screen | 320×240 landscape (BSP hardware rotation) |
| Art | 320×180 RGB565 canvas |
| Dialogue band | y 180..239, 60 px, 16 px font, 3 lines |
| Font | 16 px CJK, line height 19, 3,802 codepoints, 0 missing |
| Lists | full-screen header + up to 7 compact rows or 3 card rows |
| Title | scenic art + 300×86 logo, menu rows at x 206..314 |
| CG viewer | full 320×180 complete fit, caption band |

Controls:

- Dialogue: **UP** press = next page/line (while typing, reveal the page);
  hold **UP** = fast-forward, release stops; **DOWN** short = history;
  hold **DOWN** = auto-read; **OK** = in-game menu.
- Choice/map: UP/DOWN select, **OK short** confirms; **OK long** opens the
  menu. Auto/fast-forward always stop at a choice.
- Lists: UP/DOWN move, OK executes, **OK long** returns to the explicit source
  page (menu, title, slots, routes, gallery, ...).
- The real BSP sequence is used: PRESS → RELEASE → delayed CLICK for a short
  press, PRESS → LONG → RELEASE for a long press. A PRESS navigation marks the
  tail CLICK as consumed; a long press never eats the next independent short
  press.
- All LVGL access is under `bsp_lvgl_lock()`. Button callbacks only enqueue.

## 3. Build, pack and fonts

The pack is generated from the source snapshot, never hand-edited:

```bash
python tools/summer_pack.py \
  --source <rw5-snapshot> \
  --out main/summer_data/summer_pack.bin \
  --report build/summer_pack_report.json \
  --scene-w 256 --scene-h 144 --scene-quality 20 \
  --portrait-w 120 --portrait-h 150 --portrait-quality 30
```

`tools/summer_pack.py` parses `catalog.js`, `assets.js`, `gallery.txt` and
`converted-story/*.json`; it does not import the audit. The pack is embedded
with `EMBED_FILES`.

Fonts: `assets/fonts/gal_cjk_16.c` and `gal_cjk_20.c` are generated by
`tools/gal_font.py` from Noto Sans SC and the character inventory
(`assets/fonts/gal_cjk_symbols.txt`, built from the pack chartab plus every
non-ASCII literal under `main/`). Both are generated for `--check`; the
firmware links **only 16 px** because 20 px would add about 600 KiB and the
flash budget is reserved for story/CG/expressions. The settings page therefore
does not offer a font-size choice.

```bash
python tools/gal_font.py --font <NotoSansSC.ttf> --out-dir assets/fonts
python tools/gal_font.py --check --out-dir assets/fonts
```

## 4. Pack format

One little-endian pack, `SUMMPK01`, 25 sections. No decompressor and no JSON
parser at runtime.

| Section | Contents |
| --- | --- |
| TEXT / CHARTAB | 12-bit codepoint indices (0 terminates); 974,200 codes, 1,461,300 B |
| OPS / OPIDX | varint op stream; one u32 byte offset per 32 ops for O(32) jumps |
| SCENE / SCENE_INDEX | 40-byte scene records (name, map-name, raw date, date label), id→index table |
| CHAPTER / ROUTE | 252 chapters, 14 routes |
| GALLERY / GALLERY_ITEM | 136 groups, 712 variant image indices |
| IMAGE / IMAP / IMGDATA | 1,326 image records, source id→image map, JPEG + RLE masks |
| EXPR / EXPRIDX | postfix expression bytecode, no runtime JSON |
| VARS | 640 source variable ids |
| CHOICE / CHOICE_ITEM | var, value and condition per item |
| MAP / MAP_ITEM / MAPLABEL | 27 groups, 918 values, 946 destination hints |
| FLOWLABEL | 137 flow labels + 223 flow dates |
| PROGRESS | clear flags, heroine/flow endings, globals, ReSTART var |
| META | entry scenes, counts, title strings, logo/title images |

Expressions support `v` (including computed keys and the source's special
`24006` clear-count), `s` (date string), `string`, `native` (0), unary and
binary arithmetic, bitwise, comparisons and `&&`/`||`. The audit evaluates every
condition under six deterministic variable assignments and compares it with a
direct reimplementation of `engine.js`.

### Source-faithful VM semantics

The pack stores **four** text forms that the source uses for different purposes:
the raw `strings[106]` date (full-width digits and month/day characters,
for example U+FF17 U+6708 U+FF12 U+FF19 U+65E5 for July 29), the catalog
ASCII date label, the base map name, and the `fullName` speaker/scene label.
The VM keeps the raw date value opaque; `sceneLabel` converts it to ASCII for
display and falls back to the catalog/flow/parent date only when the raw value
is empty. Entering a scene with no date must not clear the previous date. The
display converter accepts only a complete month/day suffix (the day marker is
three UTF-8 bytes), converts fullwidth digits, rejects short/incomplete/overlong
suffixes, and returns false rather than truncate when `cap` is too small. It
never changes `vm->date` or the `EX_DATE` branch.

The top-level pack table rejects `header_size > size` immediately after the
20-byte header, before reading any section record; it also rejects duplicate
types, offsets inside the header, overlapping non-zero spans, and fixed counts
whose `count * width` is not exactly the section length (strict multiplication).
Zero-length spans are allowed and skipped by the overlap check. A guard-page
probe covers 20/24/28/32-byte buffers with `total == size`, and the maintained
test covers 0..19 plus 20/24/28/32/64/419/420.

A map preview is a **single step**: copy the VM, run until the first scene
change, and stop. The destination and its entry cursor are used for the
route/RB90 filter and `mapLabels` hint. It must not run on to the next TEXT
through `return → flow → next callScene`; those unreachable destinations are
exactly the F1 defect. The same-state source/C trace is the regression:
`281:793` has 4 destinations `[1,13,14,15]` and first destination 102, not 33
items or scene 29.

The save format is version 2. `map_bits` is 256 B and its length is a `u16`;
version 1 used a `u8`, which wrapped 256 to 0 and silently dropped every
visited bit. Version 1 saves are rejected explicitly instead of being
misread. A save preview is 20 UTF-8 **characters** plus an ellipsis, not 20
bytes.

## 5. Image policy

- Source scene assets are 320×180 RGB (16:9), not 4:3. They are scaled to
  **256×144** at JPEG q20 and displayed as a complete 320×180 frame (1.25×
  moderate upscale), never cover-cropped.
- Portraits are 292 RGBA PNGs (252 deduplicated poses + 40 added expressions).
  Each is scaled into a 120×150 box, encoded as RGB JPEG q30 and paired with a
  row-RLE 1-bit alpha mask (not PNG at runtime). The whole body is shown at
  up to 144×180 bottom-center; transparent pixels are not drawn.
- All 712 gallery variants (136 groups) are packed. The title logo is packed as
  a portrait-mask image at 300×86.
- 57 source image ids have no file in `assets.js`; the source falls back to
  `bg_black`, and the pack does the same by mapping them to the black entry.
  No missing id is silently replaced with another scene.
- Decoding uses TJpgDec callbacks directly into the 320×180 canvas. A portrait
  JPEG that fails mid-stream rolls the art back to the complete background
  (or a clear black placeholder when there is no background) before reporting;
  it does not leave a half-decoded body on screen. The notice, image-error
  state, cache invalidation and next-attempt retry are unchanged, and a failed
  image never unlocks a CG. Saving/loading a bad image is rejected by a
  header/mask probe before the VM state changes.

## 6. Persistence

NVS is 88 KiB (`0x9000..0x1F000`), the app partition is at `0x20000` (ESP-IDF
requires 64 KiB alignment), 8,257,536 B.

- Settings: text speed (instant/typewriter), auto speed.
- 30 manual save slots; 3 visible per page; overwrite confirmation.
- One **independent automatic save** (`auto`) used by "Continue"; manual slots
  never contain it.
- Story progress/unlocks: 14 clear bits, ReSTART stage, six globals, 136 CG-seen
  bits. It is loaded at startup; changing it marks dirty and retries on
  title/gallery/ending/sleep.
- A version 2 save stores scene/cursor/page/root/mode, sparse non-zero
  variables, call stack, image ids, date, all 256 map-visited bits (u16 length),
  a clear/seen snapshot and CRC32. Restoring validates version, length, CRC,
  scene, cursor, page, images and stack **before** touching the live VM; a
  failed load keeps the current state. Version 1 is rejected, not migrated.
- The save list distinguishes an empty slot from an occupied slot whose NVS
  read failed: the empty case reports that the slot has no save; the occupied
  case reports a save-read failure and asks the user to retry (the list row
  says the save cannot be read), and the live VM is untouched.
- `nvs_set_blob` and `nvs_commit` must both succeed before success is reported
  and the RAM slot is updated. A failed write keeps the old preview. NVS
  initialization failure degrades to read-only; **nvs_flash_erase is never
  called**.
- Loading an older save merges only newly seen CG/clear bits into the global
  record (OR, never reset).

## 7. Flash and RAM

Measured from the clean 2026-11-02 build:

| Item | Bytes |
| --- | --- |
| Pack | 6,425,838 (`3a7e95…`) |
| App image | 7,585,296 (limit 8,257,536; margin 672,240) |
| Merged full image | 7,716,368 (limit 8,388,608) |
| 16 px glyph bitmap | 435,960 (object `.rodata` ≈473.8 KiB) |
| Static DRAM | 269,222 / 321,296 (83.79 %); link-region free 52,074 |
| `.bss` / `.text` / `.data` | 193,224 / 68,698 / 7,300 |

`idf.py size` reports 52,074 B, but that is the **linker-region remainder**
(`dram0_0_seg` 321,296 B), not the allocator heap. The clean build has
`_bss_end = 0x3fcc1d58`, `_heap_start = 0x3fcc1d60` and
`APP_USABLE_DRAM_END = 0x3fcdc710` (IDF C3 `SOC_ROM_STACK_START 0x3fcde710`
minus 0x2000), so the allocator span is 108,976 B. Runtime deductions are the
BSP LVGL draw buffer (240×40×2 = 19,200 B), ESP LVGL port task stack (7,168 B),
main task (3,584 B), esp_timer (3,584 B), event task (2,304 B) and the input
task (**8,192 B**), totalling 44,032 B. About 64,944 B remains before LVGL
objects (CLIB malloc), NVS page cache and fragmentation. The input stack was
raised from 4 KB to 8 KB after target `-fstack-usage` showed the app/model/
TJpgDec chain worst case at about 2.9 KB; that is a static upper-bound estimate,
not a runtime high-water measurement.

Runtime free/largest-block, frame time and physical interaction were **not**
measured on a device, so they are listed as unverified.

## 9. Known limitations

- 20 px font is generated for the coverage check but not linked; only 16 px is
  offered.
- Title BGM and voice are omitted (flash budget; the RW5 source has no story
  BGM/voice anyway).
- No playable minigames, maps, animations or PC-only content that the RW5
  source already simplified. Map exhaustion is a **strategy-dependent** source
  behavior, not a universal fact: with last-choice/first-map both the source and
  C stop at `281:1404`; last-choice/last-map reaches ending 13. Map stages that
  exhaust every destination show the same documented source-style error page
  ("this map stage has no supported story options").
- Chapter entry intentionally does not synthesize clear flags/endings; only
  story mode writes ending progress.
- The source assets are the rights holder's; this branch is local technical
  validation and does not distribute the pack or a community release.

## 9. Source boundaries and non-goals

This port keeps the range of the RW5 source snapshot. It does not add PC-only
minigames, and it does not invent new story or ending branches.

- **Table tennis (scenes 280/414).** The source tags both scenes as
  table-tennis scenarios (`90_...` / `RB90_...`); `previewMap()` excludes those sources
  and the pack/production map filter carries the same `flags&2` exclusion.
  The ten choice groups (146-151, 178-181) are therefore not normal map
  destinations. The C reader retains the route-11 chapter entry after Pocket
  clear for the dialogue-only sections, but this is a chapter entry, not a
  normal story/map route. Groups 148/149 and 178-181 additionally depend on
  the missing native table-tennis producer/state. No native game, no fixed
  victory result and no save v3 are added.
- **Empty map.** If every destination of a map stage has already been visited,
  the source `renderMap()` shows its documented empty-map error page.
  The C reader shows the same error page (`app_enter_map` ->
  `APP_PAGE_ERROR`) and returns to the title. It does not auto-pick a
  destination and does not treat the empty map as an ending. In the audited
  495-item inventory this is the `SOURCE_EMPTY_MAP` state of group 47 item 1
  (the "do not take" choice); it is an actual failure state, not a pass.
- **Manosaba CommonBad.** The converted source has no reachable producer for
  `CommonBad13`: `System_Subroutine` op111/op112 have no caller and there is no
  time-out consumer. The real failure path is trial HP reaching zero
  (`trialFail`), which the port already reproduces. The port does not inject a
  `commonBadEndId` or fabricate that branch.
