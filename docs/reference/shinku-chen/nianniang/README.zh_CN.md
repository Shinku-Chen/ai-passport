## 画面几何：为什么不裁切

上游的素材是用 `Image.open(src).convert("RGB").resize((336, 480))` 产出的 —— 对未知
原图做了一次各向异性拉伸，**没有裁切**。原始宽高比在仓库里没有任何记录，所以本移植
不假装还原它：

- 背景、CG、标题图统一缩放到 **168 × 240**，居中画在 320 × 240 的黑色画布上
  （fit：不裁、不再额外拉伸）；
- 立绘缩放到高 240（宽 120），只裁掉 alpha 透明边，底部居中叠在画面上；
- 90px 对话框压在画面上，不透明度可调（10–55%，默认 30%），画面下半部仍然可见。

"按猜测的 16:9 重新拉伸" 也实测过（会裁掉左右各 12.5% 宽），**刻意不用**：原比例未知时
它只会把画面弄错。可行性报告里的 `H0`/`H1` 两档就是这么分的。

## 数据管线

```
上游 checkout ──tools/nn_pack.py──> assets/nn/nn_pack.bin   (622,892 B)
                        │                ├── SEC_TEXT     (59,574 B，NUL 结尾)
                        │                ├── SEC_IMAGE    (77 张：16 背景 / 15 CG / 15 缩略图
                        │                │                  / 30 立绘 / 1 标题)
                        │                └── SEC_OP       (1,581 条 × 12 B 定长记录)
                        └── assets/nn/nn_charset.txt ──tools/gal_font.py──> assets/fonts/gal_cjk_1{6,0}.c
```

资源包直接编进应用镜像（`target_add_binary_data`），固件把它当普通 `const` 内存读：
没有分区查找、没有 mmap 窗口、没有解压、没有 JSON 解析。

图片编码：背景/CG 用 **JPEG**，立绘用 **JPEG + 1bpp 遮罩**。解码走 TJpgDec 直写
320 × 240 RGB565 画布（`main/nn_image.c`）：输出回调把每个 MCU 转成 RGB565，立绘
则按遮罩位丢弃透明像素。全程只有**一块**大缓冲（153,600 B），没有逐图解压缓冲，
立绘也不需要第二层 LVGL 图像。

## 剧情分支

两处选项决定结局，且“选项直接进结局”不会线性掉进下一段：

```
chunk001..003 → chunk004 ─[选项]─┬ "当场推倒"      → chunk013@end_1_4_1 → 报警结局
                                 ├ "滚远点！…"     → chunk013@end_1_4_2 → 关系破裂
                                 └ "我是直男。"（空跳转＝顺序继续）
                                   └→ chunk005..011 ─[选项]─┬ "什么也不做" → chunk013@end_1_11_1 → 室友结局
                                                           └ "亲上去"（空跳转）→ chunk012 → 真结局
```

`tests/test_nn_script.c` 会遍历每条分支并断言：选项 1 的映射是 {结局1, 结局2, 继续→选项 2}，
选项 2 的映射是 {室友结局, 真结局}；四个结局各到达一次；1,248 句对白全部可达。

## 引擎要点

- `main/nn_pack.[ch]` —— 资源包解析，全部带边界检查（魔数、版本、段区间、逐条记录区间、
  跳转/选项目标）。坏包在 `init` 阶段被拒绝；宿主测试会喂截断与损坏副本。
- `main/nn_script.[ch]` —— 12 字节定长操作的解释器。只有 `SAY` 与 `CHOICE` 会停；
  背景、CG、立绘、章节标题、特效、跳转一路执行到下一个阻塞点。执行循环有上限，
  跳转成环会变成可见错误而不是卡死。
- `main/nn_canvas.c` —— 持有 RGB565 画布与交给 LVGL 的 `lv_image_dsc_t`；
  背景/CG 居中 fit，立绘底部居中。
- `main/nn_ui.c` —— 320 × 240 上的 11 个页面：标题、正文、选项、菜单、存档（5 手动 +
  1 自动）、设置、历史、鉴赏室网格（每页 6 张）、CG 全屏、结局、关于。
- `main/nn_save.[ch]` / `main/nn_save_codec.[ch]` —— NVS 持久化：存档记录带 scene/op 与
  画面状态，读档不需要重放剧本；CG 与结局解锁独立于槽位。记录用定长编码（`NSN1` 魔数、
  版本、载荷长度、字符串强制 NUL 结尾），读档前还要再用当前资源包校验一次，坏档/旧档会
  明确报错而不是恢复出乱码。**阅读器从不调用 `nvs_flash_erase()`**：NVS 是整机共享分区，
  打开失败时只降级为“现在能读、存档不可用”并给出原因，`tests/test_nn_store_contract.py`
  会守住这条。
- `main/nn_jpeg/` —— ChaN 的 TJpgDec R0.03，直接编译（绕过 LVGL 封装，因为它会先解成整幅
  RGB888）。保留原始版权声明，只去掉了 LVGL 配置引用与 `LV_USE_TJPGD` 条件编译。

顺带修掉的两处框架限制：框架的 CG/结局是 8 格/32 位硬上限，对话模型是线性事件表、
表达不了“选项→结局”。本作改用场景/标签/跳转解释器与独立的 CG 解锁位，两个上限都不再适用。

## 页面与按键的回归覆盖

`tests/harness_app.c` 用**真实的** `nn_app.c` / `nn_ui.c` / `nn_pack.c` / `nn_save.c` 跑在宿主上
（LVGL 用薄桩记录对象可见性与文本，NVS 用内存实现，画布/BSP 用薄桩），断言：

- 历史页（正文短按「下」与菜单「历史记录」两个入口）：浮层真实可见、行有内容、不串用关于页正文；

- 存档恢复：任意句存档后读回同一句；CG 解锁跨重启保持。

`tests/harness_save.c` 注入 `nvs_set_blob` / `nvs_commit` / `nvs_flash_init` / `nvs_get_blob` 失败，
断言：旧档保持不变、当前阅读位置不变、失败提示**可见**、成功提示可见，且全程 **0 次** `nvs_flash_erase()`。

`tests/test_nn_pack.c` 用真实包 + 11 类坏包（图像越出数据区、段重叠、段数 32、段表内指、重复段类型、
截断、魔数/版本/总长、记录数溢出等）验证 **fail closed**。

## 按键事件语义（PRESS / LONG / CLICK / RELEASE）

按键组件一次物理按键会依次产生 **PRESS → RELEASE → CLICK**（长按是 **PRESS → LONG → RELEASE**）。
`nn_app_key()` 里所有导航动作都只在 **CLICK / LONG** 上执行，PRESS 与 RELEASE 不触发任何页面跳转；
唯一的 RELEASE 用途是「上键松手 = 停止快进」。这一点由 `tests/harness_app.c` 的真实事件序列覆盖
（历史/结局/关于/CG 浏览四页各按一次只前进一次，且下一次正常按键仍然有效）。

## 资源包校验口径

`nn_pack_init()` 现在做**完整**的结构校验：段类型必须在已知白名单内（TEXT/META/IMAGE/SCENE/
OP/SPEAKER/CHOICE/ENDING；`NN_SEC_COUNT` 只是段表容量），段不得重叠或重复，段不得覆盖段表，
记录数×记录大小不得溢出，图像偏移不得越过该段的数据区，且**所有文本引用**（场景名、选项、
结局名/正文、说话人、SAY/CHAPTER 操作）都必须在 text 段内并以 NUL 结尾。坏包在初始化阶段就失败，
不会留下半可用的 pack。`tests/test_nn_pack.c` 用真实包 + 17 类坏包验证。

## 内存预算（同次 MAP，独立复核后修正）

- 启动可用堆：`0x3FCDC710 − 0x3FCA6450` = **221,888 B（216.7 KiB）**
- 运行期动态占用（逐项来自配置/源码，不是口头值）：

| 消费者 | 字节 |
|---|---:|
| main 任务栈（`CONFIG_ESP_MAIN_TASK_STACK_SIZE`） | 3,584 |
| esp_timer 任务栈 | 3,584 |
| 系统事件任务栈 | 2,304 |
