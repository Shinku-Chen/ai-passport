# 9-nine- 雪色雪花雪之痕 · AI Passport 离线移植

这是《9-nine- 雪色雪花雪之痕》（Episode 4）的 AI Passport 移植：320×240
横屏、三键操作、完全离线的视觉小说阅读器。固件内置已加工的第 4 部 graph、
全部正文、全部可达分支与两条结局记录；运行时不需要网络、账号或 PC。

## 来源与范围

- 上游手表移植：<https://github.com/xuanyide01/9-nine-rw5>
- 固定提交：`6a8907a5ae576f4377abe4b74f15bd9af13efe07`（第 4 部工程
  `nine-yukiiro-rw5`）
- 权威输入：仓库内已加工的 `converted/graph.json`、`graph.js` 与 143 个
  剧情分片；本移植**不**重建未提交的 PC 原作脚本。
- 剧情清单：212 个 graph 节点、12,666 条源记录（12,665 条正文 + 1 条 OP
  标记）、23 章、47 个选项节点 / 70 条选项记录、19 组 CG / 108 个变体、
  2 条结局元数据、78 个运行期变量。
- 正文：668,498 字节 UTF-8，84 个 zlib 正文块（单块最大 8,192 字节）。
- 路线：D02 三分枝与 D20 四分枝完整保留，包括按源顺序首次匹配的 `next`

  再次提供同一分枝的节点，或该分枝条件已不成立。它们仍保留在包内以保持
  完整；63 条可达选项边由 C/JS 差分轨迹覆盖。
- 结局：n112 的 `loop1` 完成解锁主视觉 2；n211 的 `true` 完成到达终止卡。
  一次完整通关会同时写入两个永久位，与源阅读器一致。

## 适配内容

- 320×240 横屏，只通过 BSP 公开的方向 API 设置。
- 保留框架页面、三键、分页、持久化与永久结局资格；标题主视觉、CG 鉴赏、
  章节目录、结局回顾、OP 与两首音乐使用本作真实素材。
- C 端复刻源引擎语义：永久键合入、首次匹配 `next`、条件筛选后的选项回退、
  章节试读隔离、500 跳上限、稳定存档游标；不重建原作 PC VM/脚本解释器。

## 操作

方向固定为横屏；旋转后 OK/UP/DOWN 仍是逻辑键。

| 页面 | 短按 OK / UP / DOWN | 长按 |
| --- | --- | --- |
| 启动 | 进入标题 | — |
| 标题 | 移动 / 确认 | 长按下切换已解锁主视觉 |
| 正文 | **推进下一个完整分页；没有下一页则下一句**（打字中或自动阅读中也照样推进，目标页直接整页显示） | OK：游戏内菜单；UP：达到阈值立即整句快进，此后每个输入 tick 最多一句；松手停；DOWN：自动阅读开关 |
| 选项 | UP/DOWN 移动，OK 确认 | OK：游戏内菜单 |
| 游戏内菜单 | 移动 / 执行 | OK：返回正文 |
| 存读档 / 设置 / 历史 / 鉴赏 / CG 列表 / 章节 / 音乐 / 关于 | 移动或执行 | OK：返回 |
| CG 全屏 | UP/DOWN 切换，OK 返回 | OK：返回 |
| 鉴赏 → OP 播放 | 短按 OK 播放真实 OP 画面与片头音轨；短按 OK 跳过；自然播完回到同一 OP 行 | OK：跳过/返回 |
| 结局 | OK 回标题 | OK 回标题 |

菜单会分别记住打开菜单时的剧情页与子页返回目标。存读档（含取消、空槽）、
设置、历史返回后恢复同一正文分页，或完整选项及原选择位置；菜单动作不推进
VM，也不授予永久进度。成功读档恢复存档中的 preview/正式状态。

鉴赏室 OP 与剧情 OP 共用音频位置时钟和“每 tick 最多一帧”渲染；不触碰
剧情 VM、存档、试读状态、永久进度或解锁。首帧或音频启动失败会可见地返回
鉴赏室，不推进剧情。

快进使用专用整句事务：跳过当前句剩余分页与打字/自动等待；每个输入 tick 最多一句，没有 90/120ms 累积或 catch-up；松手立即停，遇选项/结局/OP/资源错误停住，绝不替玩家选项，也不推进失败帧。长按松手不会再补一次短按。自动阅读在
选项处停住；手动短按会退出自动并推进。章节试读不写自动进度，也不写永久进度。

### 阅读页几何

阅读画面是完整的 320×180 16:9 图，位于 y0..179；没有 20px 黑条、裁切或
拉伸。正文面板为 y180..239（60px），按真实字体行高加 1px 行距容纳 3 行
完整 16px 或 2 行完整 20px 正文。说话人名牌在面板上方的画面上，带紧凑的
半透明背景和 8px 水平内边距，最大宽度 160px，超长名称用省略号；底边固定
在 y179，真实字形行高与内边距可向上延伸，但绝不裁切。空名称同时隐藏文字
和背景。提示与 Auto 使用独立位置；阅读页没有 “1/1” 页码 HUD。

## 构建与验证

ESP-IDF 5.5.3、ESP32-C3、8 MB Flash、无 PSRAM：

```bash
source <ESP-IDF-v5.5.3>/export.sh
idf.py build
idf.py merge-bin -o "$PWD/build/FoloToy-AI-Passport-full.bin"
python3 tools/verify_firmware.py build
python3 tools/archive_firmware.py create build --archive-root build/firmware
python3 tools/archive_firmware.py verify build/firmware/<archive>
```

宿主/静态检查（源仓库只需只读，可在仓库外）：

```bash
NINE_SOURCE=<固定-9-nine-rw5-源目录> CC=<宿主C编译器> ./tools/validate.sh --static
```

设置 `NINE_SOURCE` 会启用源到包审计与源 JS/C VM 轨迹差分；未设置时这两项
显示 SKIP，离线包、应用、图像和字库测试仍会执行。

本 worktree 证据：源到包审计 0 错误；36 条源 JS 轨迹 / 457,632 步 / 0 失败；
生产阅读器状态机与严格选项/菜单返回回归 PASS；1,057 个包内资源全部真实解码，源美术参考合成的
三通道绝对差均值 13（最大 62）；字库覆盖 2,467/2,467。设备验收为 E 固件的
**有限 USER PASS**（姓名/正文布局；完整鉴赏 OP 播放、声音与返回；快进松手停；存读档与字号分页）；
不扩展为全流程、全路线、长稳、掉电、NVS 或全部硬件通过。

## 失败与启动行为

- 图像层分配或资源包绑定失败会进入明确的中文可见“不可阅读”错误页，不再降级为仅文本；
  New/继续/读档/章节入口与正文短三键、自动、快进全部拒绝。
- 单帧图像解码失败时正文可见，但游标推进、解锁、永久进度、自动进度和手动存档全部阻止；
  短按只重试该帧，恢复后再次按键才推进。OP 失败为致命错误；标题/CG 失败显示可见提示。
- 启动顺序为输入队列 → 按键回调 → 输入任务 → ready 门控 → 开背光。任一步失败会回滚
  回调/任务/队列并保持背光关闭。首帧 `lv_refr_now` 只表示刷新请求/逻辑周期，不宣称
  物理面板 flush 已完成。
- 启动使用 4 KiB main task 栈；自动存档临时缓冲改为堆分配，不再占 1120 B 启动栈；首帧绘制链按目标 `.su` 预算复核。图片包 CRC 扫描改为查表并周期性让出 CPU，同时保留整包与逐资产 CRC 拒绝。
- 目标与真实 LVGL 测试都使用 32 KiB 池。不显示右侧值的列表不再创建值标签，使 8 行 CG
  窗口与 7 行设置可以放下；真实 19 页运行的最低池空闲为 2,224 B。

## 已知限制

- OP 为 4 fps（441 个真实源帧；110.180 秒），两首 BGM 为 8 kHz IMA ADPCM，以适应
  8 MB 无 PSRAM 目标。实测 5 fps/551 帧图片包为 6,272,593 字节，与 8,193,232 字节
  应用合计无法放入 8,323,072 字节 factory 分区；4 fps 保留完整时长、所有剧情/CG/字体
  字节及 110.184 秒片头音轨，只对源视频采样，是实测帧率取舍，没有削减其他质量。
  这也是相对手表源（320×180/5 fps OP、36 kbps Opus）的明确降采样，不是
  比特一致的媒体搬运。

OP 与单资源 CG/标题帧走单资源路径：一次严格资源 CRC/边界检查、一次 JPEG
解码直接写现有 5 条 band、一次清像素与一次 invalidation。旧路径每帧会做两次
JPEG 解码（验证 + 渲染）和三次 CRC；新路径在解码失败时于 LVGL 锁内清全部
band，不发布半帧，由应用显示故障且不推进/不写进度。
- 立绘使用 192 色索引；背景/CG 使用 JPEG q38。
- 7 条选项记录被源 graph 自身条件门控为不可达；它们保留在包内，但忠实
  游玩时无法选中。
- 仅 `true` 终止卡可达；`loop1` 是中盘完成记录，用于解锁主视觉 2。
- 未精简的框架在 32 KiB 池下无法完成菜单页刷新（仅余 684 B）；现在对不显示右侧值的列表不再创建值标签，使 8 行 CG 窗口和 7 行设置能在 32 KiB 内完成（真实宿主最低空闲 2,224 B）。
- 阅读器没有“返回上一步”按键，因此 VM 只保留 1 个检查点，而不是源引擎的
  24 项 undo 环；这在无 PSRAM 的 C3 上省下 24 份完整变量快照。历史文本
  （24 行）是独立功能，在行预算内完整保留。
- 设备验收仅限上述 E 固件已检查范围；构建、merge、分区布局、归档、宿主状态机与
  可控时钟输入结果只是宿主证据。全部路线/结局、长稳、掉电与 NVS 持久性及全部硬件项仍未验证。
