# 《9-nine- 天色天歌天籁音》移植与实现说明

本文记录在 `feature/galgame-framework` 基线上针对本作的改动。框架的通用界面与持久化
契约见 [`../development/engineering/galgame-framework.md`](../development/engineering/galgame-framework.md)。

## 1. 来源与归属

- 来源：`https://github.com/xuanyide01/9-nine-rw5`，提交
  `6a8907a5ae576f4377abe4b74f15bd9af13efe07`。
- 权威剧情是已加工的 Watch graph（`src/common/graph.js`）与其提交的正文分片
  `src/common/story/**`；`converted/graph.json` 用于交叉核对和 script/label 名称，
  不重建 PC 原始脚本。
- 打包器不写入源 checkout，也不运行源工程里依赖 PC 数据的预处理脚本。
- `tools/nine_pack.py` 对 `src/common/` 与 `converted/` 下每个文件计算摘要并写入剧情
  包头；独立审计工具重新计算并比对。任何分片、图片或元数据改动都会使包/源绑定失效。
- 源仓库代码为 MIT；游戏文本、美术、音乐版权归 Palette / 9-nine- Project，资源仅用于
  个人离线阅读，本仓库不授予再分发权。

## 2. 内容与语义

| 项目 | 数量 |
| --- | ---: |
| 节点 | 56 |
| 正文帧 | 10,385 |
| OP 标记 | 1 |
| 章节 | 21 |
| 选项组 / 选项 | 4 / 7 |
| 结局元数据 | 2 |
| 视觉快照 / 图层 | 2,119 / 8,143 |
| 图像 | 1102 |
| CG 组 / 差分 | 22 / 72 |
| 变量 | 15 |

读取器是小型 graph 解释器，不是原作 PC VM：

- `locate()` 在游标到达 `count` 时结算节点 effects，再返回正文/OP、选项或下一节点。
- 选项按 `when` 过滤；过滤后为空时回退到全部选项（源 `visibleChoices` 行为）。
- `next` 按源顺序匹配，第一条满足的生效。
- 变量数组按包内真实键数动态分配（本作 15，上限 128），不压成固定 8/32 位；
  effects 支持 `=` 与 `+`，条件支持 `all`、`==`、`!=`、`<`、`<=`、`>`、`>=`。
- 永久键写入永久进度记录；条件求值时只把 `loop1` 从 progress 合入，与源 `flags()` 一致。
- 章节/CG 回想以 `preview=true` 运行：跳过永久写入与结局 complete，试读不会污染永久进度。
- 历史保存 24 个检查点；graph 跳转上限 500；存档记录带版本、包身份、CRC 与页号。

## 3. 包格式与运行时布局

`tools/nine_pack.py` 产出两个文件，由 `tools/nine_container.py` 封装为一个 assets 分区镜像：

- `nine_script.bin`：256 B 头（版本 2）、节点/正文帧/zlib 正文块/视觉/图层/变量/条件/
  effects/边/章节（带 preview）/结局/CG 表、UTF-8 字符串池、头部保留区的源摘要。
- `nine_images.bin`：JPEG 背景、8 行分块的索引立绘/表情差分、OP 帧记录、两条音频记录、
  三张标题主视觉与 logo。每条记录有 CRC；索引图在解码时按调色板索引重新校验 CRC。
- `nine_assets.bin`：64 B 容器头 + script + images。Flash 映射层先校验容器 CRC，
  再交给 `nine_pack_open()`。

阅读页为满幅布局：16:9 画面占满 320×180（y 0..179），没有黑边或裁切；正文面板严格位于 y 180..239，显示 3 行完整 16px 正文（26 个半角单位，13 个汉字）或 2 行完整 20px 正文（20 个单位，10 个汉字）。说话人名牌是压在画面底部的半透明胶囊，按名字收紧（最多 160px）；自动/通知占用同一行右侧固定位置。

美术画布为 240×135 RGB565，拆成 5 条 240×27 带（总 64,800 B，单次分配 12,960 B），
由 LVGL 放大到 320×180。这样每次连续分配都小于 32 KB，同时保留对话框和 CG/OP
说明区。打包时从源 432×243 一次缩到 240×135；JPEG q42；立绘与差分保留 RGBA 合成和
源锚点。

## 4. 界面与按键

保留框架的 19 个逻辑屏，针对本作做以下调整：

- 通过 `bsp_lvgl_set_landscape(true)` 使用 320×240 横屏。
- 标题主视觉 1/2/3 按永久进度（`loop1`/`loop_sr`、`true`/`cf_sr`/`clear_true`）解锁，
  设置页在已解锁主视觉间切换。
- CG 鉴赏按 4 组/页分页（共 22 组），CG 查看页切换 72 张差分；缩略图由真实包解码，
  不是占位色块。
- 剧情页列出 21 章；选中后先显示章节过场，再以试读模式开始。音乐页播放两条真实音轨。
- 鉴赏室增加独立的「OP 鉴赏」行：无需通关即可播放完整 623 帧 @5 fps + 12 kHz OP 音轨；自然结束或短按/长按返回同一鉴赏室行，浏览保持静音。
- 阅读页：
  - 短按 OK/上/下始终推进一个完整单元：长句先翻下一分页，否则下一句；
    打字中或自动中都不会吞掉按键而不推进；
  - 长按 OK 进菜单，松手不会额外补一次短按推进；
  - 长按下切换自动阅读；自动等打字完成后 900 ms 推进；
  - 按住上立即按每个控制 tick 推进一句，不依赖打字或自动间隔；松开立即停；遇到选项/结局停住；
  - 自动中手动短按仍会推进，并关闭自动，不会出现“只退出自动、吞掉推进”；
  - 正文 CRC 或图像解码失败会显示可见错误并保持 VM 游标不动；可以重试当前帧，
    但不会跳过缺失内容。
- 选项页：短按上/下移动选择，短按 OK 确认；长按 OK **直接进入菜单**，不先退回正文、
  不移动 VM；从菜单返回时恢复完整选项列表和当前 choice_sel。
- 二级页长按 OK 返回；切换页面清理自动/快进/打字等待状态。

按键策略位于 `main/nine/nine_reader.c`，由 `tests/test_nine_reader.c` 用可控时钟和
游标模型覆盖：typing 中与自动中每个短键都必须改变分页/句游标。

启动顺序：`bsp_lvgl_set_landscape(true)` 必须在 LVGL 锁内成功；失败时保持背光关闭并停止
启动，不回退竖屏。UI 或可见错误页建立后固定等待 40 ms 再打开背光；这只是调度余量，不是
“LVGL flush 完成”的证明（真实首帧刷新未验收）。队列/输入任务/按键初始化失败会回滚。
所有 UI 创建与 setter 都在 `bsp_lvgl_lock()` 内。

## 5. 持久化

`main/nine/nine_store.c` 在 NVS `nine` 命名空间维护三类独立记录：

- 3 个手动槽位：元数据 + VM 存档 blob，记录 CRC 与包身份；
- 自动进度：VM 状态 + 页号，不承担永久回滚；
- 永久进度：`loop1`/`loop_sr`/`cf_sr`/`clear_true`/`titleBg` 等。

读取旧手动存档时会合入最新永久进度，已完成的真结局不会被旧档回退。读取试读存档保留
preview 标记，且不写永久进度。损坏或包身份不匹配的记录会标为损坏并拒绝读取，不会应用
到 live VM。

## 6. 媒体

- 音频为 12 kHz 单声道 IMA ADPCM（两轨），由独立任务解码后经 `bsp_audio_write()`
  播放，不依赖 Opus 运行时。
- OP 为 623 帧 JPEG @5 fps，124.66 秒；帧在 LVGL 任务上走同一套
  有界图像路径解码。
- 两者都是 8 MB Flash 下的明确预算取舍，不声称保留原始媒体保真度。

## 7. 验证

- `tools/validate.sh --static` 会编译并运行：
  - 真实 pack + VM 遍历（计数、正文、选项、真结局路线、轮回分支、试读隔离、
    存档往返与损坏拒绝）；
  - 合成条件/all/effects/first-match/回退用例；
  - 按键时钟（短按/长按/自动/快进/释放/切页清理）；
  - NVS 槽位/进度/永久记录与主机故障注入；
  - IMA 媒体解码与曲目元数据；
  - 生产图像解码器对 Pillow 参考合成的 MAE 对比；损坏的 JPEG 背景与索引立绘帧在覆盖画布前
    被拒绝，应用映射为可见错误并阻止游标前进；
  - 三条真实选项序列的冻结源 JS 轨迹差分（30,871 条视图记录，含 n4 第 3 项）；
  - 字库覆盖（2,258 字形，0 缺字）。
- `python tools/nine_audit.py` 还会逐帧对账正文、说话人、图层、选项、条件、effects、
  章节、结局、CG 差分、图像 tag、OP 时序、音频记录与源摘要。
- `./tools/validate.sh --firmware` 用 ESP-IDF 5.5.3 构建、合并 assets 分区镜像、
  校验分区布局并生成调试归档。

设备验收仍为 NOT RUN：物理按键时序、面板横屏 MADCTL、扬声器响度、深睡唤醒与长时间
阅读下的 heap 余量都没有在真机测量。

## 8. 已知限制

- 画面按 240×135 打包后放大到 320×180，画面内的小字会比源图软。
- OP 使用完整 623 帧 @5 fps 源帧序列；音频为 12 kHz 单声道。仅 OP 播放期间，五条美术带使用最近邻缩放并省去一次多余的整幅清屏；静态阅读/CG 保持原有抗锯齿缩放。OP 结束日志会记录 `end=natural|skip|error`、帧/渲染/间隔计数、音频喂数与 LVGL render/flush 边界；这些是端口测量，不是玻璃响应或帧率证明。
- 框架的 3 个手动槽位替代源移植版的 30 槽。
- 源 graph 对轮回分支只有结局元数据；轮回节点以提示和标题主视觉解锁呈现，真结局使用
  结局页。
- CG 缩略图为 48×27 以控制 RAM；CG 查看页与 OP 仍以 320×180 显示。
