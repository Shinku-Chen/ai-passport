# 死馆阅读器

把 [xuanyide01/shinuyakata-rw5](https://github.com/xuanyide01/shinuyakata-rw5)
的《死に逝く君、館に芽吹く憎悪》运行内容移植到 GalGame 框架。
基座为 `feature/galgame-framework` 的 `7f04b554`；2026-11-05 核对时它已包含
上游 `main` 的 `488beda4`。开发分支为 `feature/port-shinuyakata`。

## 内容与限制

源版本固定为 `76bba0bb0bfcc066ce6a35883d76c5b19981e0cb`（RW5 0.3.7）。
实际运行目录含 99 个源场景拆成的 198 个页面、17,409 条正文记录、11 组选项、
56 组 CG 与 311 张 CG 差分。这些统计来自实际运行文件，与上游 README 的
17,394 条统计不同。目录中全部正文均保留，包括源版控制/诊断文本；不补写剧情或结局。

从新游戏可达 196 个运行页面、全部 11 组选项和 8 个结束出口。
源页面 `n_s303_2` 和 `n_s601_2_2` 不可达；后者被源版明确标为“未解析的原作出口”。
两者仍保留在资源数据中，不将其擅自改写为新的可玩分支。本次移植的是所提供的数据集，
不代表已独立核验原商业游戏的完整性。

源版没有提供语音、BGM 或 OP 视频。因此音乐页显示空状态，不播放占位旋律。
原作美术和剧本版权归 BUG SYSTEM 及各权利人；源移植自编代码使用 MIT，
并不授予原作素材的使用权。内容含成人、暴力与惊悚元素，关于页保留提示。

## 界面与操作

320 × 240 横屏阅读器沿用框架的标题、对白、选项、菜单、设置、历史、存档、章节、
鉴赏、回想和结局页。RW5 舞台按比例缩到 320 像素宽：背景 320 × 180，y=0；
立绘保持比例、水平居中、底边统一 y=196。半透明对白框贴底 80 像素，名字牌在框外上方，底板随文字宽度加留白伸缩。
16px 与 20px 两档均显示 3 行，分页使用实际字体换行结果。标题菜单位于右侧，CG 每页 4 列×2 行；
次级页面的列表在独立视口中滚动。界面创建前，持 LVGL 锁通过 BSP 完成硬件旋转。界面内存池为 96 KB，保证历史、章节和鉴赏等已创建页面同时驻留。分页末尾的换行不再生成多余空行；覆盖存档提示适配两档字号。

- 阅读：短按确定/上/下补全当前文字或推进一页。
- 长按确定打开菜单；长按上立即快进，不额外等待，可连续跨章，松手、遇到选项或结局停止；
  每个输入循环推进一页以保持按键响应。长按下切换自动阅读。自动阅读中第一次
  动作键先停止自动，并消耗该动作。
- 列表：上/下选择，确定进入，长按确定返回；到头停止，不循环。
- CG 鉴赏：56 组全部可访问，每个窗口 8 个格子。查看时上/下切换组内差分，
  确定或长按确定返回。
- 章节和回想使用有限窗口，避免为每个剧情场景都申请 LVGL 控件。
- 3 个手动存档及自动进度保存事件、页码和全部路线变量；解锁状态独立保存。
  NVS 命名空间为 `yksave`、`ykprog`、`ykunlock`，不导入其他框架游戏的存档。
- 章节跳转和 CG 回想会从清空的路线变量开始；精确恢复当前周目请用存档或继续游戏。
- 旧竖屏及 90 像素对白框存档保留当前句和路线变量，首次读取时从该句开头重新显示，避免新旧分页不同而漏字；新横屏存档仍精确恢复页码。

自动阅读在正文打完后停 900ms，自动跨越章节卡、等待选项；只要自动模式仍开启，
包括等待选项时都保持常亮。手动阅读沿用框架空闲策略：60 秒调暗、180 秒熄屏、
420 秒深睡，任意键唤醒。

## 离线重建

运行输入保存在 `assets/yakata-source/`，`MANIFEST.json` 记录源提交和逐文件 SHA-256。
包含本移植用到的目录、剧情 JSON、背景、CG、透明立绘及上游许可证。
源仓库没有提供原始引擎脚本和音频。

```text
python tools/yakata_import.py
python tools/gal_font.py --font <NotoSansSC-Regular.otf> --out-dir assets/fonts
./tools/validate.sh
```

导入需要 Pillow。固定 quality=24，输出 `main/yakata_data/yakata_art.bin`
（5,109,188 字节），生成的正文表和纯 C 路线解析器在 `main/gal/`。
输入和生成物均保留，普通 checkout 可以离线构建。字体使用 SIL Open Font License
下的 Noto Sans SC；保留生成子集、字形清单与生成器，源字体由命令参数提供。

背景/立绘在电脑端预合成，按编码内容去重。仅在换图时用静态 4 KB TJpgDec 工作区解码。
98,304 字节共享 RGB565 缓存容纳一张 256×192 主图，或八张原生 64×40 缩略图；
按局部行读取并扩展主图到 320×240，逐字显示和重绘只读取缓存像素。这样会损失少量
图像细节，以适应无 PSRAM 板卡的内存限制。原 JPEG 信息回调含 4 KB 局部缓冲，在真机
上导致 LVGL 任务栈溢出，因此已注销。无需文件系统分区、Wi-Fi、蓝牙或联网下载。
保持普通 NVS/PHY/factory 分区布局。

## 横屏真机故障与缓存修复（2026-11-05）

及 320×240 横屏。用户反馈操作慢、画面刷新慢、鉴赏闪退。本版本 **Device tests: FAIL**。
串口抓到两次栈保护故障及重启。匹配归档 ELF 将 PC `0x4204d5be` / `0x4204d5c0`
定位到 LVGL TJPGD 的 `decoder_info()`；其 4 KB 局部缓冲超出了 7,168 字节 LVGL

`0.1.2-shinuyakata` 用有界像素缓存替换该路径，同图不重复绑定图片源，页面切换时恢复
正文/缩略图缓存。保留栈保护及原任务栈大小。正文、分支及 NVS 格式不变。需批准并刷入
这次确切的修复构建后，才能验证实际帧耗时、剩余堆及长时间鉴赏稳定性。

独立的实际 LVGL 回归工程 `tests/yakata_lvgl/` 检查主色、局部重绘内容、多次刷新不重复
解码、真实打字定时器、同图翻页、全部剧情图片、311 张 CG 差分、56 组缩略图、返回正文、
两档字体和弹窗边界，使用同样的 96 KB LVGL 池。它是常规门禁的补充，需原生 C/C++ 编译器
及已解析的 LVGL 依赖。在忽略的构建目录运行，使 PPM 截图仅保留本地：

```text
cmake -S tests/yakata_lvgl -B build/yakata-lvgl -DCMAKE_BUILD_TYPE=Release
cmake --build build/yakata-lvgl
cd build/yakata-lvgl
./yakata_lvgl ../../main/yakata_data/yakata_art.bin
```
