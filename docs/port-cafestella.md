# Café Stella Port Notes

## Source and scope

- Source: `xuanyide01/cafestella-rw5` at `90ddb9e020970907b61ad4181f25c65267e6e98b`.
- The source is a processed REDMI Watch 5 port: `converted/graph.json`, `converted/n*.json`, `src/common/engine.js`, `src/common/story/*.txt`, images, faces and audio.
- The C port reads a purpose-built pack generated by `tools/cafe_pack.py`; it does not re-run the watch packer or mutate the read-only source.
- Scope: 923 nodes, 53,727 dialogue frames + one OP marker, 69 choice groups/141 options, 7 main endings, 5 after stories, 189 chapter entries, 121 gallery groups/1,631 variants, 1,850 source images.

## Code layout

| Path | Role |
| --- | --- |
| `main/cafe/cafe_pack.[ch]` | Section index, bounds/CRC checks, zlib block cache, frame/choice/next/asset accessors |
| `main/cafe/cafe_vm.[ch]` | `engine.js`-equivalent cursor, flags, derived rules, conditions, completion, history |
| `main/cafe/cafe_store.[ch]` | NVS settings, 3 manual slots, auto progress, permanent unlock/CG bits, CRC rejection |
| `main/cafe/cafe_image.[ch]` | JPEG + 2 bpp mask + portrait/face compositing into three 224×42 bands |
| `main/cafe/cafe_input.[ch]` | Pure three-key short/long state machine |
| `main/cafe/cafe_ui.[ch]` | 320×240 LVGL pages, lists, typewriter, gallery, chapters, modal |
| `main/cafe/cafe_app.[ch]` | Page/selection state, reading advance, auto/FF policy, save/load |
| `main/main.c` | Boot, landscape, input queue, idle/dim/sleep, battery |

`assets/cafe/cafe.pak` is linked into the factory app with `target_add_binary_data`, so there is no extra data partition and `idf.py flash`/`merge-bin` carry the content. The pack is 6,424,952 bytes; the app is 8,246,672 bytes in the 8,323,072-byte factory partition (76,400 bytes free).

## Pack format

- 128-byte header: `CSPK1` magic, version, header size, file size, section count, source-manifest SHA-256.
- Section table: type/offset/size/count/CRC32. Small tables are checked at boot; text blocks and images are checked when read/decoded.
- Text frames are serialized as `kind, speaker_len, text_len, bg_asset, sprite_count, sprites[8], speaker+NUL, text+NUL`, split into blocks of ≤8,988 raw bytes (754 blocks). A 12 KB cache is the only decompression workspace.
- Sprite coordinates are pre-laid-out by the packer for the 224×126 stage; assets map to one base image plus an optional face-atlas image and patch rectangle.
- Images: 1,997 story records (JPEG + optional 2 bpp mask, 3,464,731 B) plus 287 OP records (224x126 q15, 620,030 B); total 2,284 records / 4,084,761 raw B (3,360,348 after dedup). Story backgrounds q10, title backgrounds q18, portraits/atlases q18 4:4:4.

## VM semantics

`cafe_vm_locate` follows the source exactly:

1. `@end` returns END.
2. `index < frames` returns TEXT or OP.
3. At the node tail, unless `progression == chapter`, every `complete` key is OR-ed into permanent progress.
4. Choices return CHOICE; otherwise the first `next` whose `when` matches is taken.
5. A missing target or condition is an error, never a silent linear fallback.

`flags()` starts from the current-run flag bytes, adds `flagRules` derived values and computes `checkAnyClear` from the five main route bits. `choose` writes the option effect and jumps. History holds 24 snapshots; `skip_chapter` follows the source's next-OP/chapter-change rule. The `kan_flag == 3` condition remains unreachable because no source effect writes it.

## Persistence

- Settings: speed, 16/20 px tier, auto default, panel opacity, title background mode.
- Three manual slots and automatic progress: node, frame index, run flags, permanent progress, progression mode, last completion, chapter label. Each blob has magic/version/size/CRC; invalid blobs are rejected without touching live state.
- Permanent unlock: main/after progress bits, 121 CG seen bits, last cleared route. New Game clears only run flags; loading merges the permanent progress rather than regressing it.
- Chapter previews (`progression=chapter`) do not write completion or permanent progress.

## Image pipeline and memory

- Three 224×42 RGB565 bands (56,448 B total) are the only persistent stage buffers; LVGL scales them to 320×180.
- Per band: a 224×42 RGB565 staging area, a portrait JPEG (max 224×126) decoded through TJpgDec, a 2 bpp mask, and a 106×44 patch workspace. Single allocation/workspace blocks stay below 32 KB.
- Backgrounds are centred in 224×126; portraits use source-map stage coordinates; face patches are sampled from the 133×133 atlas and alpha-blended.
- Static DRAM in the input-diagnostic build: 239,250 / 321,296 B used, 82,046 B free. The input task stack is 4 KB; `-fstack-usage` shows a worst self-frame of 1,120 B (`show_frame_page`) and an image chain of about 500 B.
- Image CRC is verified before compositing; on failure the bands are cleared and the UI shows a visible error, never a stale frame.

## Reading panel layout

The bottom dialogue panel is 60 px high at y180..239; the full art stage remains
0..179. Small text is 16 px / 3 complete lines with 1 px leading; large text is
20 px / 2 complete lines. The text object is positioned from font line height
and panel interior, not from the old fixed 4/3-line constants. App pagination is
on-demand (`gal_text_page_bounds`/`gal_text_page_count`) with no 16-page array
cap, so long source sentences, mixed text and manual newlines are not truncated.
The auto badge has a fixed 47x23 slot at x264..311/y154..177 in the image area;
it is set only after text and is hidden on Choice/Menu/Title/OP pages. The name
is above the panel, width-limited and ellipsized. A small integer-scale edge fix
(367/256) makes the three bands cover x0..319; the panel begins at y180.

### Speaker name fit

The name label background is measured from the actual selected 16/20px font
glyph run plus 8px side padding, capped at 230px total; short Chinese/Latin
names no longer retain a full-width dark strip. Long names use `LONG_DOT` and
stay left of the fixed Auto slot x264..311. Width is recomputed on every
`set_text` and on font switch; empty names hide both text and background. The
name remains above the panel and does not enter the body text area.

## JPEG segment dedup and OP 8 kHz

All 2284 JPEGs (1997 story images + 287 OP frames) are byte-preserved while
repeated marker segments are shared: a pool of exact DQT/DHT/APP/SOF/SOS/SOI/EOI
segments plus per-image descriptors and entropy literals. TJpgDec reads the
fragments directly; no whole-JPEG copy or large stack buffer is added. The
descriptor uses explicit offsets/lengths, never padded C-struct offsets; pool
and descriptor sections are CRC-checked at load. Every image and mask was
reconstructed byte-identically and decoded.

The OP audio is 8 kHz mono IMA (373,760 B data, 743,959 samples / 92.995 s),
while title stays 4 kHz and is doubled to the 8 kHz codec. OP playback does not
double an 8 kHz stream; the 92.4 s source guard, 95.46 s video tail, seek,
retry, busy-ACK stop and deep-sleep behavior are unchanged. The pack is
6,424,952 B; app 8,246,672 B (free 76,400 B).

## ROM inflate stack safety

The ESP32-C3 ROM `tinfl_decompress_mem_to_mem` helper allocates the complete
`tinfl_decompressor` (0x2af0 bytes) on the caller stack before entering the
low-level decoder. In the input task this overflowed the 4 KiB task stack during
NewGame and chapter preview. The reader now calls ROM `tinfl_decompress`
directly with a per-call heap-owned `tinfl_decompressor`; the ROM low-level
frame is 0x100 bytes and no shared decompressor state is kept. Allocation
failure returns `false`, so the caller reports a reading fault and the story
cursor is not advanced. The packed text (zlib/Adler, length, CRC) and image mask
formats are unchanged. `tests/test_cafe_inflate.c` decompresses every text block
(754), checks CRC, and rejects corrupted/truncated streams; target disassembly
evidence is in the delivery report.

## Frame-art cache

`last_art_hash` is trusted only when `last_art_valid` is true; a zero hash is
not a valid sentinel. The hash covers the background asset and semantic sprite
fields (asset/left/top/opacity/reserved), not struct padding. Text advances and
textual `enter_location` use the cache; a genuinely different visual re-renders.
Title, CG, OP, resource fault, new game, preview, save/load rebind and app
initialization invalidate the cache. A fresh render re-verifies CRC/JPEG; same
visual text skips both scene decode and verify. FF emits one bounded summary
per segment with steps, wall time, max step time, scene calls and verify calls.

## Recall and fast-forward contract

The gallery record is packed as `u16 first_variant, u16 count, u8 section,
u8 adult, u32 label_off, u16 first_node, u16 reserved, u16 reserved`; the
reader reads the unaligned label at `+6` and first node at `+10`. The previous
`+8/+12` padded-struct offsets made all recall/CG labels blank.

Recall has an explicit six-row visible page. The selection is a global index
over all unlocked groups; each page rebuilds only its visible labels, and OK
resolves the same global index to the group's exact `first_node`. Zero unlocked
groups shows an explicit unlocked-CG empty-state label plus an unlock explanation; it is never a blank
list and never grants a fake unlock. Sixteen and twenty-group controlled tests
cover first/last rows, page changes, labels and highlight.

Long UP at the 500 ms threshold enters the next sentence immediately: it skips
typing and every remaining page of the current sentence, then advances the VM
exactly once. Each input control tick advances at most one sentence; there is no
60/90/120 ms sentence accumulator or catch-up loop. Release stops immediately
without a short press. Choice/ending/OP/resource-fault pages stop FF. Short
presses still advance one complete page.

## Gallery OP playback

The Gallery has a fifth independent row, OP Playback, with no completion gate. It
uses the same 287-frame OP JPEG timeline and 8 kHz OP audio as the story OP:
short OK skips, long OK returns to the same row, natural end returns there too.
It does not touch VM/flags/progression/preview/history/auto/manual saves/NVS.
Audio/JPEG fault retry preserves the gallery context; return stops OP audio.
The story OP still advances the VM exactly once. This is UI/app wiring only; the
pack (`b397...`) is unchanged.

## OP presentation and source detail

Both story and Gallery OP hide the transition eyebrow/title objects while the
video is on screen; only a control hint remains in the non-video bottom strip.
Normal chapter transitions keep their titles. The source OP frames are native
224x126 (not the old 128x72 downscale), re-encoded at q15 and mapped into the
existing 224x126 bands; all 287 frames, 3 fps, 95.460 s, the 92.4 s guard and
the 8 kHz IMA bytes are unchanged. Measured against the source, the new frames
improve both PSNR/SSIM over the old 128x72 path, but the source itself is only
224x126, so no higher-resolution detail is invented.

## Flow-fix delta

- Ending records are read at their packed `+2/+6` offsets; the app now shows nonempty title/body for all 12 records, while the old `caa05` bundle/evidence is retained.
- A long OK on CHOICE opens the menu directly. The menu records the source page and selection; closing restores CHOICE with the same `choice_sel`, or restores the exact text page when opened from GAME. Save/load/settings/history all return through the same source page.
- The strict host regressions are `test_cafe_menu_flow.c`, `test_cafe_ending.c`, `test_cafe_ending_app.c`, and the updated `test_cafe_app.c`; the pre-fix 38-check/5-FAIL and 7/7 blank-card logs remain in the supplemental/old audit directories.

## Known gaps and risks

- Audio and OP video are included (title 4 kHz, OP 8 kHz IMA; 224x126 3fps OP) but no device speaker/panel timing or heap/CPU validation has been run.
- No device test: landscape MADCTL orientation, LVGL image scaling on the real ST7789, backlight/first-frame order, and long-reading heap fragmentation remain unverified.
- The source font lacks U+FF1B, U+76CF and U+00E9; UI strings were adjusted to avoid them (full-width semicolons replaced with commas, `Café` written `Cafe` in UI). U+3000 is normalised to an ASCII space in the pack because the source font has no glyph for it.
- The 224×126 stage is a deliberate downsample; backgrounds are q10. This is visible on a 320×240 panel and is a budget decision, not source-resolution retention.
